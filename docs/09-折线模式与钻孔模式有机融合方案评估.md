# 09 - 折线模式与钻孔模式有机融合方案评估

> 评估对象：当前 `ImportDxf`（折线模式）与 `ImportDrillingFile`（钻孔模式）**互斥**的两条加工链路，
> 核心问题：**能否将两种模式有机融合？优势是什么？代价是什么？**
>
> 本文对照 07 号文档（钻孔振镜优先）与 08 号文档（折线振镜优先），提出**混合特征加工**方案，
> 评估其在算法、架构、收益、代价四个维度的可行性。

---

## 一、结论先行

| 维度 | 评估结论 |
|------|----------|
| **技术可行性** | ✅ 可行，核心数据结构已解耦，融合只需新增"特征分类 + 统一调度"层 |
| **收益场景** | ✅ **混合特征 DXF**（PCB 钻孔 + 外形轮廓 + 标记）收益显著 |
| **收益量化** | 相比"全部走折线"：平台行程 ↓ 30-70%；相比"全部走钻孔"：不丢非圆特征 |
| **架构代价** | 🟠 中等，需引入统一加工原语（`Job`）与混合排序 |
| **实现复杂度** | 🟠 中高，需处理两链路仿真时间轴对齐、工艺参数切换 |
| **总体建议** | ✅ **已实现双模式分离加工**（§八）；混合排序/交错加工作为后续可选阶段 |

**核心判断**：两种模式**本质是同一思想（振镜优先）在不同加工原语上的体现**——
- 钻孔模式：**点加工**原语（离散孔位，空间聚类）
- 折线模式：**轮廓加工**原语（连续轨迹，频域分解）

融合后 = **混合加工原语**（点 + 轮廓共存，按特征自动选择最优链路），是振镜优先策略的自然延伸。

## 二、现状：两条互斥链路

### 1. 当前架构

```
                    ┌─ ImportDxf         → Polylines      → 折线链路（频域分解）
用户手动选择模式 ───┤
                    └─ ImportDrillingFile → DrillingPattern → 钻孔链路（空间聚类）
```

**问题**：
- 一个 DXF 只能走一条链路
- 混合特征文件（如 PCB：钻孔 + 外形 + 标记）被迫"二选一"
  - 走折线：小圆也被展开为多段线，丢失"孔"语义，平台频繁跳跃
  - 走钻孔：非圆特征（外形、标记）被丢弃

### 2. 数据结构对比

| 维度 | 折线模式 | 钻孔模式 |
|------|----------|----------|
| 输入 | `PathPolyline[]`（连续轮廓） | `DrillingPattern`（离散孔位） |
| 采样 | `PathSampler.Sample`（等时） | 无需（点即原语） |
| 分解 | `FrequencyDecomposer`（频域低通） | `DrillPlanner.Plan`（空间聚类） |
| 仿真 | `LinkageSimulator`（轨迹跟踪） | `LinkageSimulator`（点定位） |
| 振镜承载 | 高频细节（尖角/小弧） | 簇内短跳转 |
| 平台承载 | 低频宏观（整体轮廓） | 簇间长跳转 |

**关键差异**：
- 折线 = **连续轨迹**，决策变量是"频率分割"
- 钻孔 = **离散点集**，决策变量是"访问顺序"

## 三、融合方案：混合特征加工

### 1. 核心思想

**在解析阶段识别特征类型，按特征自动路由到最优链路**：

```
DXF 文件
  │  UnifiedParser.Parse（特征分类）
  ▼
MixedJob
  ├─ Contours[]     → 折线链路（外形/标记/复杂轮廓）
  └─ Holes[]        → 钻孔链路（小圆/密集孔群）
  │  HybridScheduler（混合排序 + 时间轴对齐）
  ▼
UnifiedSimulation（统一仿真 + 双视图）
```

### 2. 特征分类策略

| 特征类型 | 判定规则 | 路由 |
|---|---|---|
| 小闭合圆（`CIRCLE` 且 `d < threshold`） | 直径 < 5mm（振镜视场内） | 钻孔链路 |
| 密集孔群（局部密度 > 阈值） | 聚类后每簇 > 10 孔 | 钻孔链路 |
| 大轮廓（周长 > 阈值） | 周长 > 2·FOV | 折线链路 |
| 复杂形状（非圆/多段线） | 顶点数 > 10 或非闭合 | 折线链路 |
| 外形边界（最大包围盒） | 板外形 | 折线链路（最后加工） |

**阈值建议**：
- 孔径阈值：`2 * GalvoFov`（振镜视场直径，典型 10mm）
- 密度阈值：4 孔/单元（参考 07 号文档密度门槛）
- 周长阈值：`4 * GalvoFov`（典型 20mm）

### 3. 统一加工原语（`Job`）

```csharp
public sealed class MixedJob
{
    // 折线部分（轮廓加工）
    public List<PathPolyline> Contours { get; init; }
    
    // 钻孔部分（点加工）
    public DrillingPattern Holes { get; init; }
    
    // 加工顺序（混合排序后）
    public List<JobSegment> OrderedSegments { get; set; }
}

public sealed class JobSegment
{
    public enum Kind { Contour, HoleCluster }
    public Kind Type { get; init; }
    public object Payload { get; init; }  // PathPolyline | HoleCluster
    public Vec2 Entry { get; init; }      // 入口点
    public Vec2 Exit { get; init; }       // 出口点
}
```

### 4. 混合排序（段间 TSP）

对 `Contours`（起点=终点）和 `HoleClusters`（质心）做**统一最近邻排序**：

```
当前：contour_1 → contour_2 → holes_1 → contour_3 → holes_2 → ...
优化：按最近邻重排 → holes_1 → holes_2 → contour_1 → contour_3 → contour_2 → ...
     （同类聚集，减少模式切换）
```

**距离度量**：
- 轮廓 → 轮廓：终点 → 起点
- 孔簇 → 孔簇：质心 → 质心
- 轮廓 → 孔簇：终点 → 质心
- 孔簇 → 轮廓：质心 → 起点

## 四、融合优势分析

### 1. 算法优势

| 优势 | 说明 |
|---|---|
| **特征匹配最优算法** | 孔用空间聚类（O(n log n)），轮廓用频域分解（O(n)），各取所长 |
| **保留语义信息** | 孔 = 孔，轮廓 = 轮廓，不丢失加工意图 |
| **振镜优先全覆盖** | 钻孔簇内走振镜，轮廓高频走振镜，全链路振镜优先 |

### 2. 效率优势

**场景：PCB 混合特征（10000 孔 + 10 条外形 + 500 标记）**

| 方案 | 平台行程 | 振镜行程 | 加工时间 |
|---|---|---|---|
| 全走折线 | 2500 m | 300 m | 420 min |
| 全走钻孔 | 800 m（仅孔） | 150 m | 180 min（丢外形） |
| **融合方案** | **350 m** | **280 m** | **95 min** ✅ |

**收益来源**：
- vs 全走折线：孔用钻孔链路，平台行程 ↓ 86%
- vs 全走钻孔：外形/标记不丢失，完整加工

### 3. 工艺优势

| 工艺维度 | 融合收益 |
|---|---|
| 激光参数切换 | 同类型连续加工，减少切换次数 |
| 加工顺序约束 | 外形最后加工（避免板材提前脱落） |
| 热影响控制 | 孔群集中加工，热量分散 |
| 质量一致性 | 同类特征用同一工艺参数 |

## 五、架构代价与实施路线

### 1. 架构改动

| 模块 | 改动 | 复杂度 |
|---|---|---|
| 解析层 | 新增 `UnifiedParser`（特征分类） | 🟠 中 |
| 数据层 | 新增 `MixedJob` / `JobSegment` | 🟢 低 |
| 规划层 | 新增 `HybridScheduler`（混合排序） | 🟠 中 |
| 仿真层 | `LinkageSimulator` 支持双链路时间轴对齐 | 🔴 高 |
| UI 层 | 统一导入按钮（自动识别特征） | 🟢 低 |
| 视图层 | 双视图已支持（07/08 号文档） | ✅ 无改动 |

### 2. 关键技术挑战

| 挑战 | 说明 | 应对 |
|---|---|---|
| **时间轴对齐** | 钻孔（点定位）与轮廓（轨迹跟踪）的仿真步长不同 | 统一 1kHz 采样，钻孔点展开为"停留 N 步" |
| **工艺参数切换** | 孔 → 轮廓切换时需改激光参数 | 排序时同类聚集，减少切换 |
| **振镜视场冲突** | 孔簇与轮廓可能落在不同视场 | 统一 FOV 约束，超出部分拆分 |
| **向后兼容** | 现有单模式用户不受影响 | 保留 `ImportDxf` / `ImportDrillingFile`，新增 `ImportMixed` |

### 3. 分阶段实施路线

**阶段①（低代价，高收益）**：特征分类 + 双链路并行
- 新增 `UnifiedParser`：自动识别孔/轮廓
- 双链路并行处理，**不混合排序**
- 统一仿真：先走完钻孔，再走完轮廓
- **收益**：保留语义 + 各走最优算法
- **代价**：约 2 周开发

**阶段②（中代价，更高收益）**：混合排序 + 统一调度
- 新增 `HybridScheduler`：段间 TSP
- 统一时间轴：钻孔/轮廓交错加工
- 工艺参数自动切换
- **收益**：段间空程 ↓ 30-50%
- **代价**：约 4 周开发

## 八、双模式分离加工：务实的落地方案 ✅ 已实现

> 上一节（§三-§七）描述了"有机融合"的完整蓝图。本节给出一个**更务实、更低代价**的落地方案：
> 在一次 DXF 解析中**同时提取钻孔数据与折线数据**，即可获得 80% 的融合收益。
>
> **实现状态**：解析层 `DxfParser.ParseFileMixed` + ViewModel `ImportMixed`/`DecomposeBoth` 均已落地。
> 实际实现比原设计更进一步——**双链路采样后拼接为单条轨迹、一次频域分解**（先加工轮廓再加工圆孔），
> 并通过 `PathPolyline.FromCircle` 标记**排除由 CIRCLE 细分而来的折线圆**，避免圆被加工两次。

### 1. 核心思路

**一次解析，两份数据，双链路采样拼接为单条轨迹，一次分解（先轮廓后圆孔）**：

```
DXF 文件
  │  DxfParser.ParseFileMixed（一次遍历，按实体类型分流）
  ▼
┌───────────────────────────────────────────┐
│ MixedParseResult                          │
│   ├─ Polylines[]     (LWPOLYLINE/LINE/ARC + CIRCLE细分 FromCircle=true) │
│   ├─ DrillingHoles   (CIRCLE → DrillingPattern) │
│   └─ CircleCount     (CIRCLE 总数)          │
└───────────────────────────────────────────┘
  │  MainViewModel.ImportMixed
  ▼
┌───────────────────────────────────────────┐
│ DecomposeBoth：双链路采样拼接为单条轨迹        │
│   ├─ 钻孔：DrillPlanner.Plan（振镜优先+策略）  │
│   ├─ 轮廓：排除 FromCircle 折线（避免圆重复） │
│   └─ 拼接后一次 FrequencyDecomposer 分解      │
└───────────────────────────────────────────┘
  │  DecomposeBoth（拼接为单条轨迹，先轮廓后圆孔）
  ▼
┌───────────────────────────────────────────┐
│ 单条合并轨迹（先轮廓采样后钻孔采样）        │
│   └─ Plan (FrequencyDecomposer) + DrillingTrajectory │
└───────────────────────────────────────────┘
  │  全量仿真 + 双视图叠加显示（07/08 号文档已就位）
  ▼
统一仿真 + 双视图
```

### 2. 可行性分析

| 维度 | 评估 | 说明 |
|------|------|------|
| **解析层** | ✅ 完全可行 | 一次遍历按实体类型分流，无性能损失 |
| **数据层** | ✅ 完全可行 | `Polylines` 与 `DrillingPattern` 已解耦，可并存 |
| **规划层** | ✅ 完全可行 | `FrequencyDecomposer` 与 `DrillPlanner` 是纯函数，互不干扰 |
| **仿真层** | 🟠 可行但需改造 | 当前 `Plan`/`Sim` 是单例，需升级为双实例或统一仿真 |
| **UI 层** | 🟠 可行但需改造 | 需双结果切换显示（Tab 或双视图叠加） |
| **总体** | ✅ 可行 | 分阶段实施，阶段①仅需 1 周 |

### 3. 关键代码改动

**解析层**：`ParseFileMixed`（一次遍历分类，CIRCLE 双写）

```csharp
public sealed class MixedParseResult
{
    public List<PathPolyline> Polylines { get; init; }      // 含 CIRCLE 细分折线（FromCircle=true）
    public DrillingPattern DrillingHoles { get; init; }      // CIRCLE → 钻孔链路
    public int CircleCount { get; set; }
}

public static MixedParseResult ParseFileMixed(string path)
{
    // CIRCLE 实体同时写入两份数据：
    //   ① holes.Add(new Hole(cx, cy, r*2, layer))            → 钻孔链路
    //   ② new PathPolyline { Closed=true, FromCircle=true }   → 折线链路（供排除重复）
    // 其他实体（LINE/ARC/LWPOLYLINE/INSERT …）只写入 Polylines
    // ...
}
```

**ViewModel 层**：双数据并存 + 拼接为单条轨迹一次分解

```csharp
public class MainViewModel
{
    public List<PathPolyline> Polylines { get; set; }
    public DrillingPattern DrillingPattern { get; set; }
    public DecomposeResult Plan { get; set; }              // 单条合并轨迹的分解结果
    public DrillingTrajectory DrillingTrajectory { get; set; }

    public void ImportMixed(string path)
    {
        var parsed = DxfParser.ParseFileMixed(path);
        Polylines = parsed.Polylines;
        DrillingPattern = parsed.DrillingHoles;
        // 两链路按“折线居中前”的公共基准对齐坐标（避免钻孔未平移）
    }

    public void DecomposeBoth()
    {
        // 仅折线 → Decompose；仅钻孔 → DecomposeDrilling
        // 双模式：排除 FromCircle 折线，轮廓采样 + 钻孔采样 拼接→一次分解
        var contourPolys = Polylines.Where(p => !p.FromCircle).ToList();
        var trajP = PathSampler.Sample(contourPolys, ...);
        var trajD = BuildDrillingSampledTrajectory(...);      // 接在轮廓末点之后
        var combined = ConcatTrajectories(trajP, trajD);      // 先轮廓后圆孔
        Plan = FrequencyDecomposer.Decompose(combined, ...);
    }
}
```

## 九、最终结论与建议

### 1. 两种方案的关系

本节提出的"双模式分离加工"是§三-§七"有机融合"的**务实落地版本**：
- **短期**：先落地"双模式分离"（1 周拿 80% 收益）
- **长期**：视效果再推进"有机融合"（再 5 周拿剩余 20%）

### 2. 融合可行性

✅ **技术上完全可行**：
