下面我为你从**原理、实现细节、优缺点和适用场景**四个维度，对这四种算法进行一次深度硬核对比。

这四种算法代表了解决TSP（旅行商问题）时的三个不同层级：**纯贪心构造**（NN）、**空间索引加速构造**（Grid-NN）、**数学排序构造**（Z-order），以及**迭代优化/精确求解**（TSP Ordering 泛称）。

---

### 1. 贪心最近邻 (Greedy Nearest Neighbor)

- **原理**：这是一种**序列构造**算法。从任意起点出发，在当前点的所有未访问邻居中，选择欧氏距离最近的一个作为下一个点，直至遍历所有顶点，最后回到起点（形成闭合回路）。
- **实现细节**：
  - 维护一个 `bool[] visited` 数组。
  - 双重循环：外层遍历 n 个点，内层遍历剩余 n-k 个点计算距离并取最小值。
  - 时间复杂度严格 **O(n²)**，空间复杂度 O(n)。
- **优点**：实现极简；单次计算极快（无额外内存开销）；直觉上能生成较短的局部连线。
- **缺点**：
  - **“隧道效应”**：一旦早期选错，后期会被迫跨越整个空间去连接孤立的点，产生极长交叉边。
  - **解的质量极不稳定**，依赖起始点选择，通常比最优解差 **25%~30%** 以上。
- **适用场景**：数据量极小（n < 500）；实时游戏中敌人路径点快速估算；不在意精度，只需要一个“看着像路径”的序列。

---

### 2. 网格加速的贪心最近邻 (Grid-Accelerated NN)

- **原理**：标准NN的瓶颈在于“寻找最近点”时的全局遍历。网格加速将二维空间划分为固定大小的网格（Bucket），**只搜索目标点所在网格及邻近网格内的点**，从而将找最近邻的复杂度从 O(n) 降为近似 O(1)。
- **实现细节**：
  - **空间哈希**：计算每个点所属网格索引 `(floor(x/cellSize), floor(y/cellSize))`，存入 `Dictionary<GridCoord, List<Point>>`。
  - **螺旋搜索**：对于当前点，先搜索本网格；若为空，则按“回”字形向外层扩展网格（3x3 -> 5x5...），直到找到至少一个未访问点。
  - 计算候选集内所有点的距离，取最小。
  - 总复杂度理论可达 **O(n)** 或 **O(n log n)**（取决于点分布均匀度）。
- **优点**：将标准NN加速了 **1~2个数量级**，能轻松处理百万级点集。
- **缺点**：
  - **网格尺寸（Cell Size）极度敏感**：太大退化为全局搜索，太小导致频繁空网格扩展，反而增加计算量。
  - **边界伪影**：若点恰好在网格边界，最近的邻居可能在隔壁网格，若扩展层数不够会选错点。
  - **继承了NN的质量缺陷**，且由于搜索限制，有时比标准NN跳得更“离谱”。
- **适用场景**：超大规模数据集（n > 10万），且对路径精度要求不高；地图引擎中的散点连线预览。

### 3. Z-order 分区排序 (Z-order Partitioning Sort)

- **原理**：这**不是**典型的迭代构造算法，而是一种**空间填充曲线排序**。它将二维坐标通过**位交错（Bit Interleaving）**编码成一个64位整数（Morton Code），按此整数排序后，点在一维上的顺序天然保留了二维空间的大致邻近性。TSP路径直接按此排序后的顺序生成。
- **实现细节**：
  - 对每个点 `(x, y)`，取坐标的二进制位，交叉合并（例如：`x0,y0,x1,y1...`）生成 `z_key`。
  - 使用快速排序（O(n log n)）对 `z_key` 排序。
  - 直接按排序后的数组顺序连接点。
  - 若要闭合回路，只需将首尾相连。
- **优点**：
  - **实现极其简洁**，核心代码仅需位运算。
  - **极致的CPU缓存友好**，顺序访问内存。
  - 速度极快（排序主导），且不受点聚集密度影响。
- **缺点**：
  - **致命缺陷：不保距**。在Z-order曲线上邻近，不一定在二维空间邻近（存在巨大跳跃）。
  - **无法处理非均匀分布**，若点集中在某条斜线上，Z-order会产生大量的“锯齿状”无效折返路径。
  - 无法进行局部优化，路径质量通常比NN差，甚至可能产生自交。
- **适用场景**：**数据预处理**（如DBSCAN聚类前的排序）；**数据库索引**（PostGIS的空间索引）；实时可视化中**仅需展示点云顺序**而不要求路径最短的场景；配合2-opt作为初始解生成器。

### 4. TSP排序 (TSP Ordering - 泛指)

- **原理**：这是一个**算法大类**，不特指某一种。它代表所有旨在**逼近或求得最优访问顺序**的算法。主要包括：
  - **精确求解**：整数线性规划、分支定界、Held-Karp动态规划（O(n²·2ⁿ)）。
  - **近似保证**：Christofides算法（O(n³)，保证 ≤ 1.5倍最优解）。
  - **元启发式**：模拟退火、遗传算法（GA）。
  - **局部搜索**：**2-opt / 3-opt**（最为实用，通过反转路径片段消除交叉边）。
- **实现细节（以最常用的 2-opt + NN 初始化为例）**：
  - 先用NN或贪心构造一个初始可行解。
  - 循环遍历所有顶点对 `(i, j)`，若交换 `i+1` 和 `j` 之间的路径顺序能缩短总距离，则执行反转。
  - 反复迭代直到无法优化。
- **优点**：
  - **质量极高**。2-opt能消除所有交叉边，GA/Christofides能逼近最优解。
  - 具备**鲁棒性**，无论输入分布如何，都能输出平整无交叉的路径。
- **缺点**：
  - **计算成本昂贵**。2-opt为 O(k·n²)，Christofides为 O(n³)，GA需大量迭代。
  - 实现复杂度高，参数调优繁琐（如GA的变异率、退火冷却表）。
- **适用场景**：**工业级应用**——PCB钻孔、激光切割路径规划、物流配送调度；科学计算中需要精确数值对比的基准测试；数据量中等（n < 5000）但对美观和长度有强要求的场景。

### 📊 终极对比总结表

| 维度               | **贪心 NN**    | **网格加速 NN**      | **Z-order 排序**         | **TSP 排序 (2-opt/GA)**    |
| :----------------- | :------------- | :------------------- | :----------------------- | :------------------------- |
| **核心逻辑**       | 局部最短路贪心 | 空间索引 + 局部贪心  | 维数灾难降维（Morton码） | 交叉消除 + 全局迭代        |
| **时间复杂度**     | O(n²)          | O(n) ~ O(n log n)    | O(n log n)               | O(k·n²) ~ O(n³)            |
| **路径质量**       | 差（易自交）   | 差（同NN）           | 中（但锯齿严重）         | **极高**（平滑无交叉）     |
| **内存占用**       | 极低           | 中（需存网格哈希）   | 低（仅需Key数组）        | 高（需存距离矩阵或邻接表） |
| **参数敏感度**     | 低（仅起点）   | **极高**（网格尺寸） | 低                       | **高**（迭代次数/温度）    |
| **能否处理百万点** | ❌ 不能         | ✅ **能**             | ✅ **能**                 | ❌ 不能（内存爆炸）         |

### 💡 最终选择决策树

1.  **如果数据量 > 10万**：抛弃NN和TSP优化。选 **网格加速NN**（速度快且路径比Z-order略微合理）或 **Z-order**（实现最简单，排序后直接输出）。
2.  **如果数据量适中（500 ~ 5000）且要求可视化美观**：**必选 TSP排序（2-opt）**。建议先跑一遍NN得到初始路径，再跑2-opt，这是性价比最高的组合。
3.  **如果数据量极小（< 200）且要求理论最优**：直接上 **Held-Karp DP**（属于TSP排序的精确分支）。
4.  **如果是嵌入式单片机或实时高频调用**：只能选 **Z-order**（因为连哈希表开销都承受不了，纯位运算最快）或标准 **NN**（无动态内存分配）。
